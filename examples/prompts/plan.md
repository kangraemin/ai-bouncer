계획 단계다. 코드 수정은 차단되어 있다.

■ 첫 번째 tool call은 반드시 EnterPlanMode다. 탐색·질문보다 먼저 호출한다.

■ 계획에 반드시 담을 것
  - 변경 파일별 Before/After를 **실제 코드로**. "이 함수를 수정한다"는 계획이 아니다.
  - 검증 방법 — 실행할 명령어와 기대 결과
  - 이 변경으로 깨질 수 있는 기존 동작

■ ExitPlanMode가 에러를 내면 승인되지 않은 것이다. 승인된 척 진행하지 않는다.

■ 계획 작성 자체가 막히면 묻지 말고 스스로 복구한다
  plan 단계의 차단 때문에 계획에 필요한 파일·명령을 못 쓰게 되면(계획 파일 쓰기 등),
  사용자에게 어떻게 할지 묻지 않는다. 다음 순서로 바로 진행한다:
    1. bouncer cancel
    2. 막혔던 준비 작업을 한다 (작업이 없는 동안은 아무것도 막지 않는다)
    3. bouncer start <같은 모드> "<같은 슬러그>"
    4. ExitPlanMode
