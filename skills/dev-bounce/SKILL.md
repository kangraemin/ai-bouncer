# dev-bounce

작업을 레포 설정(`workflow.yaml`)에 적힌 **모드의 단계 순서**대로 진행한다.
단계마다 할 일(prompt)은 엔진이 주입하고, 통과 조건(run)은 엔진이 실행해 판정한다.
마지막 단계까지 통과하기 전에는 멈출 수 없다.

이 문서에는 **시작 절차만** 있다. 시작한 뒤에는 주입되는 지시를 따른다.

## Step 1 — 상태 확인

```bash
bouncer scan
```

```
STATE    MINE <경로> <모드> <단계>         이 세션이 이어서 할 작업
STATE    NONE                             없음
WORKFLOW <모드> <설명>                     모드 선택지
CHOICE   <모드> <단계> <id> <방식> <이름>   시작할 때 골라야 할 항목 (방식 ask / auto)
ERROR    <메시지>                          설정 문제 — 사용자에게 그대로 알린다
```

- `MINE`이면 이미 진행 중이다. 출력 맨 끝에 붙은 현재 단계 지시를 따라 이어서 한다.
- `NONE`이면 Step 2로 간다.
- `bouncer: command not found`가 나오면 이 컴퓨터에 설치되지 않은 것이다. 사용자에게 알리고 평소대로 작업한다.

## Step 2 — 개발 작업인지 판별

- 질문·설명·코드 읽기면 스킬을 쓰지 않고 답한다.
- 무엇을 고칠지 불명확하면 AskUserQuestion으로 구체화한다.
- 개발 요청이면 Step 3으로 간다.

## Step 3 — 모드와 항목 정하기

1. `WORKFLOW` 줄로 AskUserQuestion을 만들어 **사용자에게 모드를 묻는다.** 모드는 사용자가 고른다.
2. 고른 모드의 `CHOICE` 줄을 단계별로 묶어 처리한다.
   - 방식이 `ask`면 **반드시 사용자에게 묻는다**(AskUserQuestion, multiSelect). 선택지가 4개를 넘으면 질문을 나눈다.
   - 방식이 `auto`면 **요청 내용을 보고 직접 고른다.** 무엇을 왜 골랐는지 한 줄로 알린다.
   - `CHOICE`가 없으면 건너뛴다.

AskUserQuestion을 쓸 수 없는 세션(서브에이전트, `claude -p`)이면 추측해서 진행하지 않는다.
선택지를 텍스트로 제시하고 답을 기다린다.

## Step 4 — 시작

```bash
bouncer start <모드> "<slug>" --pick <단계>=<id>,<id> [--pick <단계>=…]
```

- slug는 영문 소문자와 하이픈으로 쓴다(예: `payment-bug`).
- 고르는 단계는 전부 `--pick`으로 적어야 한다. 하나도 고르지 않은 단계는 `--pick <단계>=`로 적고, 그 단계는 건너뛴다.
- 출력에 첫 단계의 지시가 나온다. 그대로 따른다.

## Step 5 — 이후

- 끝내려 하면 엔진이 그 단계의 run을 돌린다.
  - 실패하면 출력을 보여 주며 계속하게 한다. 원인을 고친다.
  - 통과하면 다음 단계로 넘어가며 다음 지시를 준다.
- 마지막 단계까지 통과하면 끝이다.
- 단계는 스스로 넘길 수 없다. 상태·설정 파일 편집은 막힌다.
- 같은 실패가 반복되면 같은 수정을 되풀이하지 말고 다른 원인을 찾는다.
  - 연속으로 여러 번 막히면 엔진이 사용자에게 판단을 넘기라고 안내한다.
- 작업을 접을 때는 `bouncer cancel`을 쓴다.

## 명령

| 명령 | 용도 |
|---|---|
| `bouncer scan` | 상태(이어서 할 작업이면 현재 단계 지시)·모드·고를 항목 |
| `bouncer start <모드> <slug> --pick …` | 작업 시작 |
| `bouncer cancel` | 작업 취소 |
| `bouncer check` | workflow.yaml 검사 |
| `bouncer record <이름> <명령>` | 검사를 직접 돌리고 결과를 남긴다 (prompt가 시키면 이걸로 돌린다) |
| `bouncer passed <이름>` | run용: 그 결과가 최신이고 통과했는지 (아니면 exit 2) |
| `bouncer init [--defaults\|--decline]` | 레포에 켜기(빈 설정) / 기본값 써 넣기 / 켜지 않기 |
| `bouncer setup` | 레포 설정을 사용자와 대화로 정한다 — 출력된 안내대로 묻고 yaml 을 쓴다 |

## 사용자가 "앞으로 항상 ~해라"라고 할 때

이번만인지 앞으로 계속인지 애매하면 묻는다. 앞으로 계속이면 작업이 끝난 뒤에 고친다.
설정을 크게 다시 정하려면 `bouncer setup` 안내를 따른다.
1. `workflow.yaml`의 해당 단계에 넣는다.
   - 검사는 `prompt`에 `bouncer record <이름> <명령>`으로 돌리라고 적고, `run`에는 `bouncer passed <이름>`만 둔다.
   - 사람 판단이 필요하면 `prompt`에 넣는다.
   - 매번 고를 성격이면 `items`에 넣는다.
2. `bouncer check`로 검사한다.
3. 다음 작업부터 적용된다.

작업 도중에는 설정 파일 편집이 막힌다.

## 하지 말 것

- 모드나 `ask` 항목을 사용자 대신 고르기
- 상태·설정 파일 직접 수정
- run을 통과하지 못했는데 통과했다고 보고하기
